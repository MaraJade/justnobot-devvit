## Streaming, Polling, Cron, and Loop Patterns

### Streaming Patterns:

1. **Post Stream** (lines 496-580):
   ```python
   while True:
       try:
           for post in self.reddit.subreddit(self.network).stream.submissions():
               # Process posts
       except Exception as e:
           time.sleep(60)
           continue
   ```

2. **Message Stream** (lines 424-488):
   ```python
   while True:
       try:
           for message in self.reddit.inbox.stream():
               # Process messages
       except Exception as e:
           continue
   ```

3. **Threading** (lines 583-599):
   - Uses Python threading to run post and message streams in parallel
   - Both threads run as daemon threads
   - Main thread joins both threads

### Devvit Migration Strategy:

**PRAW Behavior**: Uses infinite while loops with `reddit.subreddit().stream.submissions()` and `reddit.inbox.stream()` for real-time event processing.

**Devvit Replacement**: Use **Triggers** instead of streaming
- **Post events**: Use `onPostSubmit` trigger
- **Message handling**: Devvit doesn't support inbox streaming - requires alternative approach

**Mapping**:
- `reddit.subreddit().stream.submissions()` → `onPostSubmit` trigger
- `reddit.inbox.stream()` → **Unsupported** - requires redesign using Devvit forms or menu actions
- `while True` loops → Event-driven trigger system
- Python threading → Built-in concurrent trigger handling

## Storage Usage Analysis

### Current Storage Implementation:

**PostgreSQL Database** (lines 42-98 in justnobot.py):
- **Tables**: posters, subscribers, subreddits, subscription
- **Relationships**: Foreign keys with CASCADE delete
- **Connection**: psycopg2 with Docker PostgreSQL service
- **Schema**: Relational model for subscription management

**Migration Scripts**:
- `migration.py`: SQLite to PostgreSQL migration
- `dbmigration.py`: SQL dump file execution

### Devvit Storage Migration:

**PRAW Behavior**: PostgreSQL database with relational schema, SQL queries, and connection pooling.

**Devvit Replacement**: Use **Redis** for storage

**Storage Mapping**:
- PostgreSQL tables → Redis hashes and sorted sets
- SQL queries → Redis commands (hSet, hGet, zAdd, zRange)
- Foreign key relationships → Application-level logic
- Relational schema → Denormalized Redis structure

**Recommended Redis Schema**:
- `subscribers:{poster}:{subreddit}` → Set of subscriber usernames
- `posters:{subreddit}` → Set of poster usernames  
- `user_post_count:{user}:{subreddit}` → Counter for post history
- `subscription:{subscriber}:{poster}:{subreddit}` → Individual subscription record

**Unsupported**: Complex SQL queries, JOINs, foreign key constraints, transactions (unless using Redis transactions)

## Key Migration Challenges

### Critical Issues:

1. **Message Streaming Loss**: PRAW's `reddit.inbox.stream()` has no direct Devvit equivalent. The subscription/unsubscription system requires complete redesign using Devvit forms or menu actions.

2. **Database Architecture**: Moving from relational PostgreSQL to Redis requires significant schema redesign and application logic changes.

3. **Real-time Processing**: PRAW's streaming model with infinite while loops doesn't map directly to Devvit's event-driven trigger system.

### Recommended Approach:

1. **Phase 1**: Replace post streaming with `onPostSubmit` trigger
2. **Phase 2**: Migrate PostgreSQL to Redis with new schema
3. **Phase 3**: Redesign message handling using Devvit forms
4. **Phase 4**: Implement user history with Reddit API
5. **Phase 5**: Add moderation features using Devvit permissions

### File Mapping Summary:

- `justnobot.py` → Devvit trigger handlers + Redis logic
- `comments.py` → Template strings in Devvit server
- `config.py` → Devvit settings (remove hardcoded secrets)
- `dbmigration.py` → Redis initialization in app install trigger
- `migration.py` → Not needed (new Redis schema)
- Docker files → Not needed (Devvit deployment)
